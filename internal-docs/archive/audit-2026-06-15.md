## Executive Summary

Overall: the codebase is small and navigable, but two risks remain:

1. Hidden fallback behavior still exists in discovery/status paths.
2. `src/benchmark.mjs` has become a god module.

Recent fixes moved the repo in the right direction: no npm postinstall, no npm update cache, cleaner benchmark logs. The next cleanup should focus on removing silent fallback paths and splitting benchmark concerns.

## Hidden Fallback Review

These are the main remaining violations or near-violations of “no hidden fallbacks.”

### `src/config.mjs`

Current shape:

```js
export async function loadConfig() {
  try {
    const raw = await readFile(CONFIG_PATH, "utf8");
    return { ...DEFAULT_CONFIG, ...JSON.parse(raw) };
  } catch {
    return { ...DEFAULT_CONFIG };
  }
}
```

Problem: hides corrupt config and permission/read errors as default config.

Recommended behavior:

- `ENOENT` → defaults.
- Invalid JSON / permission / other errors → throw actionable error explaining config path and problem.

### `src/managed.mjs`

Current shape:

```js
try {
  const models = await backend.scanModels();
  results.push({ backendId, models });
} catch {
  // Managed backends are optional and may not be running.
}
```

Problem: hides “backend unavailable” vs “backend returned malformed data” vs scanner bug.

Recommended behavior:

```js
{ backendId, models, status: "ok" }
{ backendId, models: [], status: "unavailable", reason }
```

Then UI can choose whether/how to show it.

### `src/backends.mjs`

`scanOllamaModels()` and `scanOmlxModels()` return `[]` for HTTP failure, malformed JSON, backend down, or timeout.

Recommended behavior:

- Either keep low-level scan functions strict and let `managed.mjs` convert failures to explicit unavailable statuses, or return typed scan results directly.
- Avoid `[]` meaning both “server has no models” and “server could not be scanned.”

### `src/process.mjs`

`fetchJson()` returns `null` for HTTP failure, timeout, invalid JSON, endpoint missing, etc.

Problem: status logic can collapse “could not check” into “not loaded.”

Recommended behavior:

```js
{ ok: true, data }
{ ok: false, reason: "timeout" | "http" | "invalid-json" | "network" }
```

For model loaded status, distinguish:

- server down
- server up, model not loaded
- loaded status endpoint unavailable
- loaded status check failed

### `src/runtime.mjs`

`latestLlamaRelease()` and `installedRuntime()` return `null` on failures. For a non-critical interactive update check, this can be acceptable, but it should be explicitly documented as “optional update check failed, skip prompt.” If user asked to install/update and it fails, failure should be explicit.

### `src/harness-pi.mjs`

`activeProviderProfiles()` uses `loadProfiles().catch(() => [])`.

Problem: corrupt profiles or profile-dir read errors silently shrink Pi config sync to only current profile.

Recommended behavior:

- Throw on profile load failure during Pi sync.
- If wanting best-effort, print explicit warning and require user confirmation. Prefer no hidden fallback.

### `install.sh`

The installer still has a PATH fallback block:

```bash
# Fallback: try to find it anywhere on PATH after install
if command -v offgrid-ai &>/dev/null; then ...
```

This may be acceptable as installer UX, but it is a second path. Consider simplifying to one source of truth: npm prefix global bin, then explicit actionable failure if binary not there.

## Recommended Refactor Plan

### Phase 1 — No-risk cleanup

1. Remove dead `{ force: false }` update args.
2. Make `scripts/release-check.sh` fail on dirty status/diff.
3. Add benchmark renderer fixture tests.
4. Fix privacy gate / `npm pack --dry-run` warning.
5. Migrate CI to current checkout/setup-node/Node.

### Phase 2 — Hidden fallback cleanup

1. Make `loadConfig()` only default on `ENOENT`; throw on corrupt config.
2. Replace managed scan silent catches with explicit backend scan results.
3. Replace `fetchJson()` null returns with typed errors where status affects user-facing behavior.
4. Remove silent unload catch in benchmark finalizer or log explicit cleanup failure.
5. Remove `loadProfiles().catch(() => [])` in Pi sync.

### Phase 3 — Structural split

Target structure:

```text
src/benchmark/
  repo.mjs             # find/link benchmark repo, load benchmarks
  prepare.mjs          # create run slot
  pi-runner.mjs        # spawn pi, collect ndjson/result files
  stream-renderer.mjs  # semantic logging
  metrics.mjs          # llama/oMLX/Ollama speed queries
  finalize.mjs         # metadata/failure/result summary
  flow.mjs             # user prompts
```

Keep `src/benchmark.mjs` temporarily as a thin compatibility facade, then delete once imports are migrated.
